## How to run the notebook

1. Make sure `Online_Retail.csv` is in the **same folder** as
   `final_proyect_updated_v3_k3_commented.ipynb` (it is already included in this ZIP).
2. Open the notebook in Jupyter or Google Colab.
3. Run **Restart & Run All**. No absolute paths, no manual steps, and no hidden cells —
   every table, figure and number is reproduced from scratch.
4. The random seed is fixed once (`RANDOM_SEED = 42`) and reused everywhere, so results are
   stable across runs.

**Files generated by running the notebook:**

| File | Contents |
|------|----------|
| `customer_segments_output.csv` | One row per customer: RFM values, assigned cluster and segment name |
| `segment_summary_output.csv` | Aggregated profile (size, revenue share, averages) per segment |
| `online_retail_segmentation_dashboard.html` | Self-contained stakeholder dashboard (charts embedded, opens in any browser) |

## Summary of results (from the real dataset)

| Segment | Customers | % of base | Avg. Recency | Avg. Frequency | Avg. Monetary | % of revenue |
|---|---|---|---|---|---|---|
| High-Value / Champions | 805 | 18.6% | 17.3 days | 13.0 orders | £7,647 | **69.3%** |
| At-Risk | 1,677 | 38.7% | 45.4 days | 3.3 orders | £1,234 | 23.3% |
| Low-Engagement | 1,856 | 42.8% | 167.8 days | 1.3 orders | £357 | 7.5% |

- **Silhouette score (held-out test set):** 0.333
- **Baseline (traditional RFM quintile scoring):** 0.230 → K-Means improves on it by **+0.103**
- **Train → test silhouette gap:** +0.002 (the cluster structure generalises well to customers the model never trained on)

The top 1% of customers (44 people) account for 32.1% of total revenue, which is why `log1p`
is applied to Recency, Frequency and Monetary before scaling and clustering — without it, a
handful of wholesale buyers dominate the distance calculation and distort the segments.
